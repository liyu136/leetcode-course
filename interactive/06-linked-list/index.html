链表不是“一排盒子”

节点可以散落在内存中。真正把它们连接起来的是每个节点内部的 .next 引用。

先观察一条链表

点击按钮切换“值视角”和“引用视角”
现在看到的是值。 但只知道 3、7、9，并不能说明谁在谁后面。

Python 节点定义

class ListNode:    def __init__(self, val=0, next=None):        self.val = val        self.next = next

val 保存数据，next 保存对下一个节点对象的引用。

head 是什么？head 只是指向第一个节点的变量，不是装着整条链表的容器。

把代码和结构对应起来

third = ListNode(9)second = ListNode(7, third)head = ListNode(3, second)
变量指向
head值为 3 的节点
second值为 7 的节点
third值为 9 的节点
third.nextNone
空链表没有第一个节点，所以直接写 head = None。
02

遍历：让 current 沿着 next 走

数组用下标移动；链表只能从当前节点取得下一个节点。

单步执行

current 指向“下一个尚未处理的节点”
result = []current = headwhile current is not None:    result.append(current.val)    current = current.nextreturn result
循环不变量current 指向下一个尚未处理的节点；result 保存此前节点的值。

为什么不能写 while current.next:？

空链表会报错

当 current is None 时，读取 current.next 相当于读取 None.next。

会漏掉最后一个节点

最后一个节点的 next 是 None，循环不会进入，因此它的值没有被处理。

链表和 Python list 的取舍

操作Python list单链表
访问第 i 个O(1)O(i)
已知节点后插入可能搬动元素O(1)
查找某个值O(n)O(n)

重要前提链表的 O(1) 插入要求你已经拿到了正确节点。如果还要先寻找它，总时间仍然可能是 O(n)。

03

插入与删除：顺序决定会不会丢节点

修改引用前，先问自己：原来的后继节点还能找到吗？

在 A 和 C 之间插入 B

初始：A.next 指向 C
  1. 创建 B
    b = ListNode("B")
  2. 让 B 先接住 C
    b.next = a.next
  3. 再让 A 指向 B
    a.next = b
危险写法如果直接覆盖 a.next = b，又没有提前保存 C，原链表后半段就可能丢失。

删除已知节点的下一个节点

# A → B → Ca.next = a.next.next# A ─────→ C

Python 中没有其他引用指向 B 时，它最终会被垃圾回收，不需要手动 free。

dummy：把“删除头节点”变成普通删除

dummy = ListNode(0, head)current = dummywhile current.next:    if current.next.val == target:        current.next = current.next.next    else:        current = current.nextreturn dummy.next
删除后为什么 current 不前进？新的 current.next 仍可能等于 target。连续的目标节点需要继续由同一个前驱删除。
04

反转链表：三个引用保住整条链

这是本讲最重要的题。不要背六行代码，要能说清 previous、current、next_node 分别指向哪里。

逐行反转 1 → 2 → 3

黄色=current，绿色=已经反转部分，紫色边框=暂存的 next_node
previous = Nonecurrent = headwhile current is not None:    next_node = current.next    current.next = previous    previous = current    current = next_nodereturn previous
  1. 保存后续
    next_node = current.next
  2. 反转箭头
    current.next = previous
  3. previous 前进
    previous = current
  4. current 前进
    current = next_node
反转循环不变量previous 是已反转部分的头；current 是未处理部分的头。两部分合起来仍包含原链表全部节点。

时间

O(n) 每个节点只处理一次。

额外空间

O(1) 只使用固定数量的引用变量。

05

合并两个有序链表

每次比较两个“未合并部分的第一个节点”，把较小者接到 tail 后面。

让 tail 构造有序前缀

list1: 1→3→5　list2: 2→4→6
dummy = ListNode()tail = dummywhile list1 and list2:    if list1.val <= list2.val:        tail.next = list1        list1 = list1.next    else:        tail.next = list2        list2 = list2.next    tail = tail.nexttail.next = list1 or list2return dummy.next
循环不变量dummy.next 到 tail 是已经确定的有序前缀；list1、list2 指向各自尚未合并的第一个节点。
为什么剩余部分可以整体接上？一个链表耗尽后，另一个链表本身已经有序，而且所有节点都不小于已合并前缀的尾部。
06

快慢指针：用速度差制造信息

slow 每次一步，fast 每次两步。fast 到末尾时，slow 恰好走到中间附近。

寻找中点：1 → 2 → 3 → 4 → 5 → 6

绿色框=slow，橙色框=fast
slow = headfast = headwhile fast is not None \      and fast.next is not None:    slow = slow.next    fast = fast.next.nextreturn slow
条件顺序不能反先确认 fast 不是 None，才能安全读取 fast.next。

偶数个节点时，这个版本返回第二个中点。上面的 6 个节点最终返回节点 4。

为什么是中点？

每一轮 slow 走 1 步，fast 走 2 步。设 slow 走了 k 步，fast 就走了约 2k 步。fast 到达长度 n 附近时，slow 走了约 n/2。

07

环与相交：比较的是身份，不是值

两个不同节点可以都保存 7。链表相遇、相交和成环关注的是它们是否为同一个对象。

快慢指针判断环

模拟结构：1 → 2 → 3 → 4 → 2 …
为什么一定相遇？进入有限长度的环后，fast 每轮相对 slow 多走 1 步，所以它会逐格追上 slow。
def has_cycle(head):    slow = fast = head    while fast and fast.next:        slow = slow.next        fast = fast.next.next        if slow is fast:            return True    return False

链表相交：走完自己的路，再走对方的路

a, b = head_a, head_bwhile a is not b:    a = head_b if a is None else a.next    b = head_a if b is None else b.nextreturn a

若长度分别是 m、n，两个指针最终都走过 m+n 的对齐路径。它们会在共同节点相遇；没有交点时，会在共同的 None 相遇。
